# ЧТЗ М-03. Проекты и станции, жизненный цикл мероприятия

**Основание:** ТЗ, ЧТЗ-4 (CAB-04 – CAB-08), диаграмма состояний (рис. 8 ВКР).
**Код:** `app/routers/cabinet.py`, `app/models.py → EVENT_STATUSES, TRANSITIONS`, шаблоны `cabinet/project*.html`, `partials/tracker.html`.

## 1. Назначение

Провести идею участника от черновика до «разбора полёта»: описать мероприятие и его станции, отправить на экспертизу, получить решение, продать билеты, внести факт.

## 2. Жизненный цикл

| Статус | Стадия запуска (в интерфейсе) | Кто переводит дальше | Куда |
|---|---|---|---|
| `draft` Черновик | Сборка | автор | `review` |
| `review` На экспертизе | Предстартовые проверки | руководитель | `evaluated`, `rework` |
| `rework` Доработка | Возврат на доработку | автор | `review` |
| `evaluated` Оценён | Проверки пройдены | руководитель | `approved`, `rework`, `rejected` |
| `approved` Утверждён | Готов к старту | руководитель | `on_sale` |
| `rejected` Отклонён | Старт отменён | — | — |
| `on_sale` Продажа билетов | Обратный отсчёт | руководитель | `held` |
| `held` Проведён | Полёт завершён | руководитель | `analyzed` (через «Внести факт») |
| `analyzed` Проанализирован | Разбор полёта | — | — |

Любой другой переход — 403. Закрытие тура экспертизы переводит `review → evaluated` автоматически.

## 3. Функциональные требования

| ID | Требование |
|---|---|
| М03-01 | Создание проекта: название, формат из классификатора (коды 10–42), дата, время, площадка, вместимость, цена, плановый бюджет, возрастной рейтинг (0+, 6+, 12+, 16+, 18+), аудитория, концепция. Код присваивается автоматически `LAB-ГГГГ-NN` |
| М03-02 | Автор меняет проект только в статусах «Черновик» и «Доработка»; руководитель — всегда |
| М03-03 | Станции: название, описание, длительность (мин), стоимость (₽), ответственный; добавить, изменить, поднять/опустить, удалить |
| М03-04 | Нельзя отправить на экспертизу проект без станций |
| М03-05 | Возврат на доработку и отклонение — только с комментарием; решение пишется в `decisions`, автор получает уведомление |
| М03-06 | Отправка на экспертизу уведомляет всех руководителей |
| М03-07 | Карточка проекта — вкладки: Обзор, Станции, Экспертиза, Прогноз и решение, Задачи, Билеты и факт, Изменить; сверху — трекер стадий запуска |
| М03-08 | Видимость: руководитель — всё; автор — свои; эксперт — назначенные; остальные — только мероприятия от «Продажа билетов» и позже |
| М03-09 | Список проектов с фильтром по статусу и поиском по названию и коду |
| М03-10 | Внесение факта: гости, продано билетов, выручка, фактические затраты, средняя оценка (подставляется из анкет). Флажок «Завершить разбор» переводит в `analyzed` и запускает пересчёт компетентности (М-05) |
| М03-11 | Каждая смена статуса — запись в `audit_log` (`старый → новый`) |

## 4. Данные

`events`, `stations`, `decisions`, `event_results`, `event_formats`, `venues`.

## 5. Интерфейсы

`/cabinet/projects`, `/cabinet/projects/new`, `/cabinet/projects/{id}?tab=…`, `POST …/status`, `POST …/stations`, `POST …/stations/{sid}` (`action=save|up|down|delete`), `POST …/result`.

## 6. Приёмка

| Сценарий | Ожидаемо | Тест |
|---|---|---|
| Участник создаёт проект и 3 станции, отправляет на экспертизу | 303, статус `review` | `test_full_flow`, шаг 1 |
| Участник пытается перевести в «Оценён» | 403 | там же |
| Руководитель утверждает → в продажу | карточка `/e/{код}` доступна | шаг 4 |
| Внести факт с «Завершить разбор» | статус `analyzed`, 4 записи истории компетентности | шаг 6 |
