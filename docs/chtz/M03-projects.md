# ЧТЗ М-03. Проекты и сценарий, жизненный цикл мероприятия

**Основание:** ТЗ, ЧТЗ-4 (CAB-04 – CAB-08), диаграмма состояний (рис. 8 ВКР).
**Код:** `app/routers/cabinet.py`, `app/models.py → EVENT_STATUSES, TRANSITIONS`, шаблоны `cabinet/project*.html`, `partials/tracker.html`.

## 1. Назначение

Провести идею участника от черновика до «разбора полёта»: описать мероприятие и его станции, отправить на экспертизу, получить решение, продать билеты, внести факт.

## 2. Жизненный цикл

| Статус | Стадия запуска (в интерфейсе) | Кто переводит дальше | Куда |
|---|---|---|---|
| `draft` Черновик | Сборка | автор | `review` |
| `review` На экспертизе | Предстартовые проверки | руководитель | `evaluated`, `rework` |
| `rework` Доработка | Возврат на доработку | автор | `review` |
| `evaluated` Оценён | Проверки пройдены | руководитель | `approved`, `rework`, `rejected` |
| `approved` Утверждён | Готов к старту | руководитель | `on_sale` |
| `rejected` Отклонён | Старт отменён | — | — |
| `on_sale` Продажа билетов | Обратный отсчёт | руководитель | `held` |
| `held` Проведён | Полёт завершён | руководитель | `analyzed` (через «Внести факт») |
| `analyzed` Проанализирован | Разбор полёта | — | — |

Любой другой переход — 403. Закрытие тура экспертизы переводит `review → evaluated` автоматически.

## 3. Функциональные требования

| ID | Требование |
|---|---|
| М03-01 | Создание проекта: название, формат из классификатора (коды 10–42), дата, время, площадка, вместимость, цена, плановый бюджет, возрастной рейтинг (0+, 6+, 12+, 16+, 18+), аудитория, концепция. Код присваивается автоматически `LAB-ГГГГ-NN` |
| М03-02 | Автор меняет проект только в статусах «Черновик» и «Доработка»; руководитель — всегда |
| М03-03 | Сценарий (spec 002): лента блоков по времени от `start_time` — вид (блок программы, служебный, карусель станций; станция — только внутри карусели), название, описание, длительность, стоимость, ответственный, отметка «оценивать». Карусель: число групп, переход; длительность = n станций × самая длинная + (n − 1) × переход. Добавить, изменить, поднять/опустить, удалить (карусель — со станциями). Время начала и конца блока считается автоматически |
| М03-04 | Нельзя отправить на экспертизу проект без оцениваемых блоков. Эксперты и гости оценивают только блоки с отметкой «оценивать» и станции каруселей |
| М03-04a | Слот площадки (мин): предупреждение, если сценарий не влезает; после проведения — фактическая длительность блоков, сравнение «план — факт» и строка «Длительность» в «Итоговой оценке» |
| М03-05 | Возврат на доработку и отклонение — только с комментарием; решение пишется в `decisions`, автор получает уведомление |
| М03-06 | Отправка на экспертизу уведомляет всех руководителей |
| М03-07 | Карточка проекта — вкладки: Обзор, Сценарий, Экспертиза, Прогноз и решение, Задачи, Билеты и факт, Изменить; сверху — трекер стадий запуска |
| М03-08 | Видимость: руководитель — всё; автор — свои; эксперт — назначенные; остальные — только мероприятия от «Продажа билетов» и позже |
| М03-09 | Список проектов с фильтром по статусу (один или несколько через запятую: `?status=held,analyzed`), «только мои» (`?mine=1`) и поиском по названию и коду. Те же фильтры вынесены в подменю «Проекты» бокового меню |
| М03-10 | Вкладка «Билеты и факт»: гости, продано билетов, выручка, фактические затраты (импорт Timepad подставляет билеты и выручку) |
| М03-11a | Вкладка «Итоговая оценка» — последний этап планирования: таблица «план → прогноз → факт» с отклонением и точностью прогноза (100 % − MAPE), попадание явки в прогнозный диапазон, станции «эксперты vs гости», голос гостей (средняя, NPS, распределение, комментарии), точность каждого эксперта и будущая компетентность; поля «Оценка гостей» и «Выводы»; кнопка «Завершить разбор полёта» → `analyzed`, `reviewed_at`, пересчёт компетентности один раз |
| М03-12 | Вкладка «Документы» (spec 004): файлы (PDF, Word, Excel, PowerPoint, OpenDocument, ZIP, TXT/CSV, картинки до 20 МБ, тип — по содержимому) и ссылки на Яндекс Диск / Google Диск с типом (смета, договор, сценарий, райдер, презентация, прочее). Видят участники проекта и руководители; файлы хранятся вне публичной папки и отдаются через `/cabinet/files/{id}` с проверкой прав |
| М03-13 | Фотоальбом: ссылка на полный альбом на Яндекс Диске / Google Диске; на публичной странице — кнопка «Все фото на …» |
| М03-11 | Каждая смена статуса — запись в `audit_log` (`старый → новый`) |

## 4. Данные

`events`, `stations`, `decisions`, `event_results`, `event_formats`, `venues`.

## 5. Интерфейсы

`/cabinet/projects?status=&mine=&q=`, `/cabinet/projects/new`, `/cabinet/projects/{id}?tab=…`, `POST …/status`, `POST …/stations` (блок сценария; `parent_id` — станция в карусель), `POST …/stations/{sid}` (`action=save|up|down|delete`), `POST …/timing` (слот площадки и факт по блокам), `POST …/result`. Таблица в БД исторически называется `stations`.
