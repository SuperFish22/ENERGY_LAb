# ЧТЗ М-01. Аутентификация, роли и журнал действий

**Основание:** ТЗ, ЧТЗ-4 (требования CAB-01 – CAB-03, CAB-09 – CAB-11), ТЗ (общее) — требования к защите информации (SYS).
**Код:** `app/security.py`, `app/deps.py`, `app/routers/auth.py`, `app/routers/admin.py`.

## 1. Назначение

Пускать в личный кабинет только приглашённых людей, давать каждому права по ролям и фиксировать, кто что изменил.

## 2. Границы модуля

Входит: вход и выход, приглашения, регистрация по приглашению, защита от подбора пароля, CSRF, роли, управление экипажем, журнал аудита.
Не входит: вход через VK ID / Telegram Login (этап 2), восстановление пароля по e-mail (этап 2, сейчас пароль сбрасывает руководитель новой ссылкой-приглашением).

## 3. Роли

| Код | Название | Может |
|---|---|---|
| `member` | Участник Lab | создавать свои проекты, видеть свои задачи, писать в обсуждения |
| `expert` | Эксперт | всё участника + оценивать назначенные проекты по критериям своего отдела |
| `head` | Руководитель | всё + назначать экспертов, открывать/закрывать туры, принимать решения, управлять экипажем, критериями, модерацией |
| `listener` | Слушатель | зарезервировано для школы вожатых (этап 3) |
| `master` | Мастер школы | зарезервировано для школы вожатых (этап 3) |

У пользователя может быть несколько ролей. Эксперт привязан ровно к одному отделу и имеет компетентность c ∈ [0,5; 1,0].

## 4. Функциональные требования

| ID | Требование | Реализация |
|---|---|---|
| М01-01 | Вход по e-mail и паролю; e-mail без учёта регистра | `POST /login` |
| М01-02 | Пароль хранится только как хеш scrypt с солью (n=2¹⁴, r=8, p=1) | `security.hash_password` |
| М01-03 | 5 неудачных попыток входа на один e-mail за 15 минут → блокировка на 15 минут, ответ 429 | `LoginLimiter` |
| М01-04 | Сессия — подписанная cookie (itsdangerous), `HttpOnly`, `SameSite=Lax`, `Secure` при `SECURE_COOKIES=1`, срок 14 дней | `SessionMiddleware` в `main.py` |
| М01-05 | Каждая форма кабинета содержит CSRF-токен сессии; POST без токена → 400 | `deps.csrf` |
| М01-06 | Регистрации «с улицы» нет. Руководитель создаёт ссылку-приглашение на 7 дней с ролями и отделом | `POST /cabinet/admin/invite` |
| М01-07 | По ссылке человек задаёт ФИО и пароль (не короче 8 символов) и даёт согласие на обработку ПДн | `GET/POST /invite/{token}` |
| М01-08 | Руководитель меняет роли, отдел, компетентность, блокирует пользователя. Ручная правка компетентности пишется в историю с причиной | `POST /cabinet/admin/users/{id}` |
| М01-09 | Нельзя снять роль «Руководитель» с последнего руководителя | там же |
| М01-10 | Журнал аудита: вход, приглашение, смена ролей, смена статуса проекта, решения, правка весов | `security.audit`, таблица `audit_log` |
| М01-11 | Неавторизованный запрос к `/cabinet/*` → переадресация на `/login?next=…` | `LoginRequired` |

## 5. Данные

`users`, `roles`, `user_roles`, `experts`, `competence_history`, `audit_log`. Первый руководитель создаётся при запуске из `ADMIN_EMAIL` / `ADMIN_PASSWORD`.

## 6. Интерфейсы

`/login`, `/logout`, `/invite/{token}`, `/cabinet/admin/users`, `/cabinet/admin/invite`.

## 7. Правила и ограничения

* Ссылка-приглашение подписана `SECRET_KEY`; смена ключа делает все выданные ссылки и сессии недействительными.
* Сообщение об ошибке входа одно и то же для «нет пользователя» и «неверный пароль».
* Заблокированный пользователь (`is_active = false`) не входит в кабинет и не опознаётся ботом.

## 8. Нефункциональные требования

Проверка пароля — не быстрее 50 мс (стоимость scrypt), чтобы подбор был дорогим. Токен бота сравнивается за постоянное время (`hmac.compare_digest`).

## 9. Приёмка

| Сценарий | Ожидаемо | Тест |
|---|---|---|
| 6 неверных паролей подряд | 6-я попытка — 429 | `test_login_lockout` |
| POST в кабинет без токена | 400 | `test_csrf_required` |
| Приглашение → регистрация с коротким паролем → с нормальным | 400, затем 303 и роль «Эксперт» отдела СМИ | `test_invite_and_register` |
| Снять роль с последнего руководителя | роль сохраняется, показано предупреждение | `test_last_head_cannot_lose_role` |
| Открыть `/cabinet` без входа | 303 на `/login` | `test_cabinet_requires_login` |
