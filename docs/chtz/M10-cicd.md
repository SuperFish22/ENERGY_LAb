# ЧТЗ М-10. Сборка, проверка и развёртывание (CI/CD)

**Основание:** ТЗ (общее), требования к системе SYS-01 – SYS-05, SYS-16; условие заказчика: доступа к серверу у разработчика нет.
**Код:** `.github/workflows/ci.yml`, `.github/workflows/deploy.yml`, `Dockerfile`, `docker-compose.prod.yml`, `deploy/nginx.conf`, `migrations/`.

## 1. Назначение

Каждое изменение проверяется автоматически, а на сервер попадает только проверенная версия — по кнопке руководителя, без передачи паролей разработчику.

## 2. Конвейер

```
push / pull request ──▶ CI: ruff → pytest + покрытие app/expertise ≥ 90 % → миграции на PostgreSQL 16 → docker build
                                         │ (только main, CI зелёный)
                                         ▼
                        CD: сборка образа → ghcr.io/<владелец>/energy-lab:<sha> и :latest
                                         ▼
                        окружение «production» — ждёт ручного подтверждения руководителя
                                         ▼
                        SSH на сервер: docker compose pull → up -d → alembic upgrade head → проверка /health
```

## 3. Требования

| ID | Требование |
|---|---|
| М10-01 | CI на каждый push и pull request: линтер ruff, тесты pytest, покрытие `app/expertise` не ниже 90 % |
| М10-02 | Проверка миграций Alembic на чистом PostgreSQL 16 (сервис GitHub Actions) |
| М10-03 | Сборка Docker-образа; образ запускается от непривилегированного пользователя |
| М10-04 | Публикация образа в GitHub Container Registry с тегами `sha` и `latest` |
| М10-05 | Развёртывание только из ветки `main`, только после зелёного CI, только после подтверждения в окружении `production` |
| М10-06 | Секреты — только в GitHub Secrets и в `.env` на сервере; в репозитории их нет (`.env` в `.gitignore`) |
| М10-07 | После развёртывания — проверка `/health`; при ошибке job падает, старый контейнер можно вернуть `IMAGE=…:<предыдущий sha>` |
| М10-08 | Миграции применяются при старте контейнера (`alembic upgrade head`), сиды справочников идемпотентны |

## 4. Секреты GitHub (задаёт заказчик)

| Секрет | Что это |
|---|---|
| `SSH_HOST` | адрес сервера в РФ |
| `SSH_PORT` | порт SSH (обычно 22) |
| `SSH_USER` | отдельный пользователь `deploy` в группе `docker`, без sudo |
| `SSH_KEY` | закрытый ключ, открытая часть которого в `~deploy/.ssh/authorized_keys` |
| `GHCR_READ_TOKEN` | токен GitHub только с правом `read:packages`, чтобы сервер скачал образ |

## 5. Приёмка

* Pull request с упавшим тестом не проходит CI.
* Слияние в `main` запускает CD, который останавливается на ожидании подтверждения.
* После подтверждения `curl https://<домен>/health` → `{"status":"ok"}`.
