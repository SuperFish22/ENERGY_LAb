# ЧТЗ М-08. API бота, бот Telegram и VK, уведомления

**Основание:** ТЗ, ЧТЗ-5 (BOT-01 – BOT-10); решения заказчика: «Telegram остаётся на внешнем сервере»; 17.11.2026 — «переписать ботов на Python вместо n8n».
**Код:** `app/routers/api_bot.py`, `app/notify.py`; бот — `bot/` (Python, без зависимостей); в n8n — только выгрузка в Google (`n8n/workflows/*.json`).

## 1. Назначение

Дать участникам доступ к кабинету из мессенджера (задачи, вопросы отделу) и доставлять уведомления, не вынося персональные данные с российского сервера.

## 2. Архитектура

```
Telegram (getUpdates) / VK (Long Poll) ⇄ bot, Python (внешний сервер) ──HTTPS + Bearer──▶ Nginx ▶ /api/bot/* (сервер в РФ)
                                              ▲                                                  │
                                              └──── раз в 15 с: очередь /api/bot/notifications ◀─┘
```

* Energy Lab сама в мессенджеры не ходит. Она складывает уведомления в таблицу `notifications`, бот раз в 15 секунд забирает их и отправляет с кнопками.
* Бот получает сообщения long polling'ом (`getUpdates`): на внешнем сервере не нужны вебхук, домен, nginx и открытые порты. При старте бот снимает вебхук, если он остался от n8n.
* Nginx пускает на `/api/bot/` только IP внешнего сервера; кроме того, нужен заголовок `Authorization: Bearer <BOT_API_TOKEN>`.
* Выкладка — GitHub Actions `.github/workflows/bot.yml` (папка `bot/` → `~/energy-bot/bot`, `docker compose up -d --build`). Проверка — `tests/test_bot.py`: бот насквозь через настоящий API сайта.
* Пользователь бота определяется парой `(channel, user_id)`, channel = `telegram` | `vk`.
* С 10.02.2026 Telegram в РФ работает с замедлением; поэтому дубль — бот сообщества VK, канал выбирает сам пользователь.

## 3. Команды бота

| Команда | Что делает | Метод API |
|---|---|---|
| `/start` | приветствие, привязан ли аккаунт | `GET /me` |
| `/link 123456` | привязать аккаунт кодом из профиля | `POST /link` |
| `/unlink` | отвязать | `POST /unlink` |
| `/tasks` («Мои задачи») | открытые задачи со сроками и кнопками «в работу» / «сдать» | `GET /tasks`, `POST /tasks/{id}/status` |
| `/ask` («Вопрос отделу») | выбрать отдел → тема → текст; создаётся обсуждение | `GET /departments`, `POST /discussions` |
| `/discussions` | 10 открытых обсуждений моего отдела со ссылками | `GET /discussions` |
| ответ (reply) на уведомление об обсуждении | сообщение в обсуждение | `POST /discussions/{id}/messages` |
| `/question` | вопрос на публичную доску (без привязки) | `POST /questions` |
| `/afisha` | ближайшие мероприятия в продаже | `GET /events` |
| `/faq`, `/faq слово`, «частые вопросы» | список опубликованных вопросов кнопками `faq:ID` (до 10), с словом — похожие (до 5); кнопка — ответ | `GET /faq?q=`, `GET /faq/{id}` |
| обычный текст от человека без привязанного аккаунта | диалог поддержки: первое сообщение — «Передали оператору» и до 3 подсказок из FAQ, следующие — без ответа бота | `POST /support` |
| ответ (reply) на уведомление с `#диалогN` | ответ оператора человеку от имени бота | `POST /support/{id}/reply` |

## 4. Требования

| ID | Требование |
|---|---|
| М08-01 | Все методы требуют Bearer-токен; неверный — 401 |
| М08-02 | Код привязки одноразовый, живёт 10 минут; повтор — 400; мессенджер, уже привязанный к другому человеку, — 409 |
| М08-03 | Непривязанный пользователь на закрытых методах получает 404 с подсказкой, как привязаться |
| М08-04 | Вопросы и обсуждения из бота: не больше 5 за 10 минут с одного пользователя (429) |
| М08-05 | SOS удалён (решение заказчика 17.11.2026): команды `/sos` и метода `POST /sos` нет (404); прежние SOS-обращения миграцией 0010 переведены в «Отклонённые» |
| М08-05a | Поддержка (spec 005): `POST /support` для привязанного участника возвращает `{"linked": true}` (бот показывает команды), для внешнего — создаёт или продолжает незакрытый диалог (`support_chats`, `support_messages`), не больше 20 сообщений за 10 минут (429). Каждое сообщение — уведомление операторам (роль `support`; если её нет ни у кого — руководителям) на сайте и в мессенджер с текстом `#диалогN · Имя (канал): …` |
| М08-05b | `POST /support/{id}/reply` — только привязанный пользователь с ролью `support` или `head` (иначе 403); ответ сохраняется с `source` = канал и ставится в очередь человеку: «💬 Поддержка Energy Lab: …». Ответ с сайта (`/cabinet/support/{id}`) уходит так же. Закрытие диалога — короткое сообщение человеку; закрытые диалоги старше 180 дней удаляет `app.maintenance` |
| М08-06 | Уведомления: новая задача, ответ в обсуждении, новый вопрос отделу, открыт тур экспертизы, решение по проекту, ответ модератора на вопрос с доски |
| М08-07 | Очередь: `GET /notifications?limit=50` — неотправленные (`id`, `channel`, `chat_id`, `text`, `reply_markup` — JSON кнопок Telegram или `{}`); `POST /notifications/{id}/sent` — отметить; неотмеченное отправляется повторно |
| М08-07a | `POST /tasks/{id}/status` доступен исполнителю, автору и руководителю (кнопка «Принять» под уведомлением); права — как на доске (`tasks_board.can_move`), повторное нажатие — без изменений |
| М08-08 | Тексты уведомлений не содержат e-mail и телефонов, только имя, название и ссылку в кабинет |
| М08-09 | Описание API в формате OpenAPI — `/api/docs` (Swagger) и `/api/openapi.json` |

## 5. Формат

Запросы и ответы — JSON, UTF-8. Пример:

```http
POST /api/bot/discussions
Authorization: Bearer ****
{"channel":"telegram","user_id":"555","department_code":"TECH","title":"Нужен второй проектор?","text":"Для зала реликвии"}

200 {"ok":true,"id":7,"url":"https://lab.example.ru/cabinet/discussions/7"}
```

## 6. Приёмка

`test_bot_api` — привязка, задачи, обсуждение отделу, непривязанный, `/sos` → 404, поддержка, очередь, ограничение частоты; `test_support_guest_operator_telegram_and_site`, `test_faq_command` — гость → оператор в Telegram (reply) и на сайте, подсказки FAQ; `test_moderation_notifies_bot_author` — ответ модератора уходит автору в мессенджер.
