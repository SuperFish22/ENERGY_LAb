# ЧТЗ М-08. API бота, n8n, Telegram и VK, уведомления

**Основание:** ТЗ, ЧТЗ-5 (BOT-01 – BOT-10); решение заказчика: «Telegram и n8n остаются на внешнем сервере».
**Код:** `app/routers/api_bot.py`, `app/notify.py`; сценарии `n8n/workflows/*.json`.

## 1. Назначение

Дать участникам доступ к кабинету из мессенджера (задачи, вопросы отделу) и доставлять уведомления, не вынося персональные данные с российского сервера.

## 2. Архитектура

```
Telegram / VK ⇄ n8n (внешний сервер) ──HTTPS + Bearer──▶ Nginx ▶ Energy Lab /api/bot/* (сервер в РФ, PostgreSQL)
                         ▲                                                    │
                         └──────── опрос очереди /api/bot/notifications ◀─────┘
```

* Energy Lab сама в мессенджеры не ходит. Она складывает уведомления в таблицу `notifications`, n8n раз в минуту забирает их и отправляет.
* Nginx пускает на `/api/bot/` только IP сервера n8n; кроме того, нужен заголовок `Authorization: Bearer <BOT_API_TOKEN>`.
* Пользователь бота определяется парой `(channel, user_id)`, channel = `telegram` | `vk`.
* С 10.02.2026 Telegram в РФ работает с замедлением; поэтому дубль — бот сообщества VK, канал выбирает сам пользователь.

## 3. Команды бота

| Команда | Что делает | Метод API |
|---|---|---|
| `/start` | приветствие, привязан ли аккаунт | `GET /me` |
| `/link 123456` | привязать аккаунт кодом из профиля | `POST /link` |
| `/unlink` | отвязать | `POST /unlink` |
| `/tasks` («Мои задачи») | открытые задачи со сроками и кнопками «В работу» / «Готово» | `GET /tasks`, `POST /tasks/{id}/status` |
| `/ask` («Вопрос отделу») | выбрать отдел → тема → текст; создаётся обсуждение | `GET /departments`, `POST /discussions` |
| `/discussions` | 10 открытых обсуждений моего отдела со ссылками | `GET /discussions` |
| ответ (reply) на уведомление об обсуждении | сообщение в обсуждение | `POST /discussions/{id}/messages` |
| `/question` | вопрос на публичную доску (без привязки) | `POST /questions` |
| `/afisha` | ближайшие мероприятия в продаже | `GET /events` |
| `/sos` | экстренное сообщение дежурным руководителям | `POST /sos` |

## 4. Требования

| ID | Требование |
|---|---|
| М08-01 | Все методы требуют Bearer-токен; неверный — 401 |
| М08-02 | Код привязки одноразовый, живёт 10 минут; повтор — 400; мессенджер, уже привязанный к другому человеку, — 409 |
| М08-03 | Непривязанный пользователь на закрытых методах получает 404 с подсказкой, как привязаться |
| М08-04 | Вопросы и обсуждения из бота: не больше 5 за 10 минут с одного пользователя (429) |
| М08-05 | SOS не публикуется на доске; ответ содержит чаты и телефоны дежурных руководителей и текст «звоните 112», n8n рассылает сразу в оба канала |
| М08-06 | Уведомления: новая задача, ответ в обсуждении, новый вопрос отделу, открыт тур экспертизы, решение по проекту, ответ модератора на вопрос с доски |
| М08-07 | Очередь: `GET /notifications?limit=50` — неотправленные; `POST /notifications/{id}/sent` — отметить; неотмеченное отправляется повторно |
| М08-08 | Тексты уведомлений не содержат e-mail и телефонов, только имя, название и ссылку в кабинет |
| М08-09 | Описание API в формате OpenAPI — `/api/docs` (Swagger) и `/api/openapi.json` |

## 5. Формат

Запросы и ответы — JSON, UTF-8. Пример:

```http
POST /api/bot/discussions
Authorization: Bearer ****
{"channel":"telegram","user_id":"555","department_code":"TECH","title":"Нужен второй проектор?","text":"Для зала реликвии"}

200 {"ok":true,"id":7,"url":"https://lab.example.ru/cabinet/discussions/7"}
```

## 6. Приёмка

`test_bot_api` — привязка, задачи, обсуждение отделу, непривязанный, SOS, очередь, ограничение частоты; `test_moderation_notifies_bot_author` — ответ модератора уходит автору в мессенджер.

## 7. Что нужно от заказчика

Токен бота Telegram (BotFather), сообщество VK с включёнными сообщениями и ключом доступа, IP сервера n8n, чат дежурных.
