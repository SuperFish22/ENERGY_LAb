# ЧТЗ М-04. Экспертиза: взвешенные критерии, Дельфи, риск станций

**Основание:** ТЗ, ЧТЗ-3 (EXP-01 – EXP-11), раздел 2.3 ВКР (формулы 1–9).
**Код:** `app/expertise/scoring.py` (метод А), `delphi.py` (Б), `risk.py` (В), `service.py`, `app/routers/expertise.py`, шаблон `cabinet/evaluate.html`.

## 1. Назначение

Собрать независимые оценки экспертов пяти отделов, свести их в одну оценку проекта и каждой станции, проверить согласованность и найти опасные станции.

## 2. Отделы и критерии (по умолчанию)

| Отдел | α | Критерии (вес внутри отдела) |
|---|---|---|
| Сценарный (SC) | 0,25 | Оригинальность идеи 0,40; Драматургия и логика сюжета 0,35; Соответствие ЦА 0,25 |
| Режиссёрско-постановочный (DIR) | 0,25 | Вовлечённость и интерактивность 0,40; Тайминг и темп 0,30; Реализуемость силами команды 0,30 |
| Технический (TECH) | 0,15 | Свет и звук 0,40; Сложность оборудования 0,35; Безопасность 0,25 |
| Продюсерский (PROD) | 0,20 | Соответствие бюджету 0,40; Площадка и логистика 0,30; Сроки и ресурсы 0,30 |
| СМИ (SMI) | 0,15 | Инфоповод и медийность 0,40; Визуальный контент для фото и видео 0,30; Потенциал охвата 0,30 |

Руководитель меняет веса в «Критерии и площадки»; система нормирует их к сумме 1.

## 3. Методы

**А. Взвешенная оценка.** Среднее по критерию с учётом компетентности: x̄ₖ = Σ cₑ·xₑₖ / Σ cₑ. Оценка отдела Dⱼ = Σ wₖ·x̄ₖ. Итог S = Σ αⱼ·Dⱼ. Если у критерия нет оценок, его вес делится между остальными критериями отдела; если не оценил весь отдел — веса отделов нормируются заново, а в заключении отдел помечается «нет оценок».

**Б. Дельфи.** Для каждого эксперта считается его собственная оценка станций Sₑ, станции ранжируются (одинаковым — средний ранг). Коэффициент конкордации Кендалла W = 12·S_R / (m²(n³ − n)), где m — эксперты, n — станции. W не считается при m < 2 или n < 3. Если W < 0,5 после тура 1 — руководителю предлагается тур 2. Во втором туре эксперт видит медиану и межквартильный размах тура 1 по каждому критерию. Туров не больше двух.

**В. Риск станций.** Каждый эксперт ставит вероятность провала P и тяжесть последствий I по шкале 1–5. R = P·I по медианам. Зоны: ≤ 6 — зелёная, 7–14 — жёлтая, ≥ 15 — красная. Риск провала мероприятия Q = 1 − Π(1 − κ·Rᵢ/25), κ = 1.

## 4. Функциональные требования

| ID | Требование |
|---|---|
| М04-01 | Руководитель назначает экспертов проекта; автор проекта в эксперты не назначается |
| М04-02 | Руководитель открывает тур (срок — по желанию) и закрывает его; назначенные эксперты получают уведомление |
| М04-03 | Эксперт видит и оценивает только критерии своего отдела; попытка прислать чужой критерий — 403 |
| М04-04 | Оценка объекта «проект целиком» и каждой станции; шкала 1–5 с подписями уровней |
| М04-05 | Балл 1–2 без комментария не принимается; во втором туре не принимается изменение своего балла тура 1 больше чем на 1 без комментария |
| М04-06 | Черновик сохраняется кнопкой «Сохранить», отправка — «Отправить»; после закрытия тура оценки не меняются |
| М04-07 | Форма оценки станции показывает зону риска сразу при выборе P и I |
| М04-08 | После закрытия тура: S проекта и станций, оценки отделов, W, зоны риска, Q; эксперты не видят чужих баллов до закрытия |
| М04-09 | Тур 2 копирует оценки тура 1 как черновики эксперта |

## 5. Данные

`criteria`, `departments`, `event_experts`, `expertise_rounds`, `evaluations` (уникальность раунд/эксперт/критерий/станция, CHECK 1–5), `risk_assessments`.

## 6. Интерфейсы

`POST /cabinet/projects/{id}/experts`, `…/rounds`, `…/rounds/close`, `GET/POST …/evaluate?station=…`.

## 7. Контрольный пример (раздел 2.3 ВКР)

Три эксперта, веса и баллы как в ВКР → S = 3,96; W ≈ 0,78; R станций = 4, 12, 16; Q ≈ 0,84. Проверяется тестом `tests/test_expertise_math.py`. Покрытие пакета `app/expertise` тестами — не ниже 90 % (проверяет CI).
