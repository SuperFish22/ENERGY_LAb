# Бот Energy Lab (Telegram, VK, уведомления)

Python-сервис вместо сценариев n8n. Работает на внешнем сервере (там же, где n8n), с сайтом общается только
через закрытый API `https://<сайт>/api/bot/*` с токеном `BOT_API_TOKEN`. Персональные данные не хранит.

```
Telegram ◀── long polling ──▶ bot (Docker, внешний сервер) ── /api/bot/* ──▶ сайт (сервер в РФ)
                                   └── раз в 15 с забирает очередь уведомлений и рассылает их с кнопками
```

* **Без зависимостей** — только стандартная библиотека Python 3.12; образ собирается за секунды.
* **Без вебхука** — бот сам спрашивает Telegram (`getUpdates`), поэтому ему не нужны домен, nginx и открытые порты.
* **Что умеет**: `/start`, `/link КОД`, `/unlink`, `/tasks` с кнопками «в работу» / «сдать», `/ask` (меню отделов),
  `/discussions` и ответ reply на `#обсуждениеN`, `/question`, `/afisha`, `/faq` (частые вопросы кнопками),
  доставка уведомлений сайта с кнопками «Взять в работу», «Сдать», «Принять», «Открыть на сайте».
  ВКонтакте — те же команды через Bots Long Poll, если задан токен сообщества.
* **Поддержка**: обычное сообщение от человека без привязанного аккаунта уходит операторам (роль «Поддержка» на
  сайте) с меткой `#диалогN`; оператор отвечает reply на это сообщение в своём Telegram или на сайте — человеку
  ответ приходит от имени бота. Первое сообщение бот подтверждает и подсказывает похожие ответы из FAQ.

## Установка на сервер (один раз)

```bash
mkdir -p ~/energy-bot/bot && cd ~/energy-bot/bot
# файлы приходят из GitHub Actions (workflow «bot»); для первого раза можно скопировать папку bot/ вручную
cp .env.example .env && nano .env        # TELEGRAM_BOT_TOKEN, LAB_URL, BOT_API_TOKEN
chmod 600 .env
docker compose up -d --build
docker compose logs -f bot               # ждём «Бот запущен: telegram, outbox»
```

`BOT_API_TOKEN` — тот же, что в `.env` сайта. Сайт пускает к `/api/bot/` только IP этого сервера (nginx, `allow`).

## Переход с n8n

1. Выкладка n8n (workflow «n8n») сама выключает старые сценарии «Telegram-бот», «доставка уведомлений», «VK-бот».
   Если она ещё не проходила — выключите их в интерфейсе n8n вручную.
2. **Сценарий «EnergeLab» в n8n использует тот же токен бота** — его тоже нужно выключить, иначе он снова поставит
   вебхук и будет перехватывать сообщения (в логах бота появится «Telegram 409»). Бот при старте сам снимает вебхук.
3. Выгрузка в Google Таблицу и документы из шаблона Google Docs остаются в n8n.

## Проверка

```bash
docker compose logs --tail 50 bot
# в Telegram: /start → /link КОД из кабинета → /tasks; с другого аккаунта — просто «Здравствуйте» → диалог в «Поддержке»
curl -s "https://api.telegram.org/bot<ТОКЕН>/getWebhookInfo"     # url должен быть пустым
```

Тесты: `pytest -q tests/test_bot.py` — бот прогоняется насквозь через настоящий API сайта (без сети).

## Устройство

| Файл | Что делает |
|---|---|
| `core.py` | разбор команд и кнопок, ответы — не зависит от мессенджера |
| `lab.py` | клиент `/api/bot/*` |
| `telegram.py` | `getUpdates`, отправка, кнопки, снятие вебхука, обработка 409 |
| `vk.py` | Bots Long Poll API, inline-клавиатура с payload |
| `outbox.py` | очередь уведомлений: отправить → отметить; 400/403 (бот заблокирован) снимаются с очереди, сетевые ошибки повторяются |
| `main.py` | потоки Telegram / VK / уведомления, остановка по SIGTERM |
